## 修复 craft-anything 桌面程序中文乱码

- 根因：`crates/ui-egui/build.rs` 把 CJK 字体作为可选构建输入（`CRAFT_FONTS_DIR`），默认不嵌入；用户构建时该变量未设置，生成的 `craft_fonts.rs` 是空表，界面只有 Figtree / JetBrainsMono 两款纯拉丁字体，中文全部显示成方块。
- 修复（用户选择"内嵌开源中文字体"方案）：
  - 下载 Noto Sans SC Regular（Google Fonts `fonts.gstatic.com`，10MB，SIL OFL 1.1）到 `assets/fonts/NotoSansSC-Regular.ttf`，许可证 `assets/fonts/OFL-NotoSansSC.txt`。
  - 改 `crates/ui-egui/src/theme.rs`：新增 `NOTO_SANS_SC` 静态字节，`install_fonts` 里注册为 `NotoSansSC` 并放入 fallback 列表首位（经 `sans_first` 排序，若日后有 craft-fonts 的脚本专用字体仍排在它前面）。
- 重新编译 `cargo build --release -p craft-anything` 通过；二进制 59MB，`strings` 确认已含 `NotoSansSC`，`install_fonts` 在 `lib.rs:718` 启动路径被调用。
- 测试：`cargo test -p craft-anything-ui-egui` 137 通过、1 失败、1 忽略。失败项 `game_files::tests::a_non_text_folder_is_refused_before_a_look_starts` 是 APFS 上用 0xFF 非法 UTF-8 字节建目录触发 `Illegal byte sequence`，与本改动无关，属既有环境问题。
- 未 commit（遵守用户 git 纪律）。

## 新增 build_macos.sh（本地打包 .app）

- 需求：一条命令产出 `Craft Anything.app`，用户自己拷贝到 /Applications。现有 `packaging/macos/package.sh` 是发布级（universal/lipo + DMG + 公证），太重，不复用其流程。
- 脚本放项目根 `build_macos.sh`（可执行），复用 `packaging/env.sh`（VERSION/BINS/HAS_CLI/CARGO_PKGS/copy_font_licences）、`packaging/macos/Info.plist.in`、`entitlements.plist`、`assets/app-icon/craft-anything.icns`。
- 关键决策：只编本机架构（`cargo build --release --locked`，不做 lipo）；输出到 `$ROOT/dist/Craft Anything.app`（可用 `LOCAL_APP_DIR` 覆盖）；**必须把 `craft-anything-cli` 一并放进 MacOS/**（`self_cli_path` 在自身二进制旁找 MCP server，缺了 Claude Code 构建全挂 #91）；ad-hoc 签名（`- --options runtime --timestamp=none`，无需 Apple 账号），由内向外签再 verify --strict --deep。
- 支持 `--skip-build`（改了资源想快速重打包时）；`--help` 打印用法。
- 实测通过：产出结构含 Info.plist/PkgInfo/icns/主程序+CLI/OFL 许可证（含新加的 NotoSansSC），`craft-anything --version` 输出 0.6.1，codesign 校验通过。安装：`cp -R "dist/Craft Anything.app" /Applications/`。

## 修复语言选择器里的方块字（格鲁吉亚/韩/泰）

- 用户截图显示语言列表有一行 7 个方块，定位为格鲁吉亚语 `ქართული`（i18n.rs `LANGUAGES` 第 4 项）。逐字核对全部 17 种语言自名，发现缺字的是**格鲁吉亚语、韩语 한국어、泰语 ไทย** 三种；Russkiy/Greek/CJK/拉丁等已覆盖。
- 调研小米字体：普通 MiSans（含 whjkd2005 等仓库的 7.6MB TTF）与 Noto Sans SC **都不含格鲁吉亚文字形**（U+10A0-10FF = 0）；只有 MiSans Global 覆盖，但它官方只给按语言切片的 web font（cs/lt，无 Georgian），CDN 无 ge/ka/georgian 路径，完整 TTF 下载困难且体积巨大。MiSans 许可还要求在软件中署名、不得单独再分发字体文件。
- 用 fontTools 检查 cmap 的方法很有效：`TTFont(p)['cmap'].tables` 合并 keys，检查 ord(ch)。
- 用户选择"补格鲁吉亚字形(推荐)"方案：下载 Google Fonts 的 Noto Sans Georgian(60K)/Noto Sans KR(5.9M)/Noto Sans Thai(45K) TTF + 三份 OFL 到 assets/fonts。
- theme.rs 改动：新增三个静态字节 + `BUNDLED_FALLBACKS: &[(&str,&[u8])]` 表；`install_fonts` 用该表统一注册（原来是硬编码 NotoSansSC 一条）。`sans_first` 会把它们都归为 Sans 级、稳定排序保持 SC→Georgian→KR→Thai 顺序，与 craft-fonts 的 Local/Cjk 不冲突。
- 新增测试 `bundled_fallbacks_show_every_language_name`（不依赖 craft-fonts）：遍历 LANGUAGES 用 `has_glyphs` 断言每个自名可显示，通过。旧的 `with_craft_fonts_every_script...` 仅在有 craft-fonts 时跑。
- 重新 `./build_macos.sh` 打包成功，app 内 Licenses 已含三份新 OFL。这些改动尚未 commit（上次 commit/push 后用户选择自己 push，本轮未要求提交）。
- Google Fonts TTF 直连可用：fonts.googleapis.com 取 css2 → fonts.gstatic.com 下 .ttf；OFL 从 cdn.jsdelivr.net/gh/google/fonts@main/ofl/<name>/OFL.txt 取。
